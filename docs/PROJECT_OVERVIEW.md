# Project overview

## What this project is

E Commerce Site is the product label for a multi-tenant business operations web app. The code currently serves hospitality and other small-business tenants. It combines property and room administration, bookings, customer records, sales/catalog, stock, expenses, receipts, and business reporting. The `retail-core` browser flow exercises authenticated product sales and receipts; it does not represent a public shopper storefront or online checkout.

## Users and implemented capabilities

- **Business owners and administrators** register, create a business, configure its modules, and manage staff and business settings.
- **Business staff** work within their active business membership. Authorization and tenant scoping are applied by API middleware and domain services.
- **Business customers/guests** are records maintained by a business. The current code has no separate shopper account experience.
- **Platform administrators:** there is no distinct cross-tenant super-admin console in the current web app.

Features evidenced in the application and API include authentication with refresh tokens and login lockout; business membership and module configuration; properties and rooms; customer records; bookings and payments; catalog products and categories; stock movements; sales and receipt records; expenses; dashboard summary; activity logging; health endpoints; and PWA shell assets. Receipt output is generated by the API and a public receipt view is present. Login uses a generic credential error, rate limiting, request IDs, structured request logging, and security headers. Payment capture is recorded by staff; no payment gateway integration is present.

## Architecture and folder map

This is a pnpm workspace with a Next.js App Router frontend, a modular Express API, shared TypeScript contracts, and PostgreSQL persistence through Prisma. The API's `createApp` factory is shared by the server and tests. Route definitions live under `apps/api/src/routes`; controllers and services are grouped by domain; validation and middleware are in their own directories. Tenant-owned data is scoped by business membership and `businessId`.

| Path                    | Purpose                                                                                                                                                     |
| ----------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `apps/web`              | Next.js web app, auth and business dashboard pages, API client, PWA shell, unit-level frontend tests, and Playwright retail flow                            |
| `apps/api`              | Express API, domain services/controllers, Prisma schema and migrations, Jest unit tests, API e2e and tenant-isolation suites                                |
| `packages/shared-types` | Shared enums, API/domain types, and integration interface types                                                                                             |
| `infra`                 | Local PostgreSQL/Adminer Compose setup and production Compose example                                                                                       |
| `docs`                  | Architecture, development, deployment, backup, tenancy, API inventory, audit history, and project notes                                                     |
| `.github/workflows`     | CI jobs for install/lint/build, empty-database migrations, unit coverage, API e2e/tenant isolation, retail Playwright, dependency audit, and aggregate gate |
| `.vscode`               | Editor recommendations/settings for contributors                                                                                                            |

The root pins pnpm `9.15.0`. CI selects Node.js `20`. The app manifests specify Next.js `^15.5.24`, React `^18.3.1`, Express `4.22.3`, TypeScript `^5.7.2`, Prisma `^6.1.0`, PostgreSQL `16` in Compose/CI, Tailwind CSS `^3.4.16`, Jest `29.7.0`, and Playwright `^1.63.0`. The API uses Zod for request validation. The exact resolved package versions are recorded in `pnpm-lock.yaml`.

## Local development

Requirements: Node.js 20+, pnpm 9.15.0, and Docker Compose with PostgreSQL 16, or a PostgreSQL 16 database. Copy the root `.env.example` and `apps/api/.env.example` to their local `.env` counterparts and supply local values; the examples contain placeholders only. Start PostgreSQL with `docker compose -f infra/docker-compose.yml up -d postgres`, then install and migrate:

```sh
pnpm install --frozen-lockfile
pnpm --filter api exec prisma migrate deploy
pnpm --filter api prisma:seed
pnpm dev:api
pnpm dev:web
```

The API listens on port 3001 and the web app on port 3000 by default. The API loads `apps/api/.env`; Next.js loads the root `.env`.

## Checks

Commands run from the root unless noted:

```sh
pnpm lint
pnpm build
pnpm --filter api exec jest --coverage --ci --runInBand
pnpm --filter api exec prisma migrate deploy
pnpm --filter api exec jest --config ./test/jest-e2e.config.json --runInBand
pnpm --filter web exec playwright install chromium
pnpm --filter web test:e2e
pnpm audit --prod --audit-level high
```

Migration and API e2e commands require a dedicated test database. Configure `DATABASE_URL` and `TENANT_TEST_DATABASE_URL` to that disposable database and never use a development or production database for the e2e suite. The CI workflow creates a clean PostgreSQL 16 service for migration, e2e, and browser jobs.

## Deployment

See [deployment](deployment.md), [backup and restore](backup-restore.md), and [development](DEVELOPMENT.md). Production runs the web app and API as separate services with PostgreSQL; configure secrets, origins, proxy trust, and Redis throttling according to those documents. The checked-in production Compose file is an example, not a hosted deployment pipeline.

## Not implemented

- Public shopper registration, a public multi-merchant storefront, shopping cart, and shopper checkout.
- Online payment gateway processing; payment records are entered by staff.
- Email, SMS, and WhatsApp delivery integrations.
- Offline/IndexedDB synchronization.
- A platform-wide super-admin UI.
- Automated public hosting/deployment configuration.
- The open issues that refer to legacy NestJS/Swagger artifacts or future integrations need review against the current Express architecture; see [issue triage](ISSUE_TRIAGE.md).
